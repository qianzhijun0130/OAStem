## 模块信息

| 项 | 内容 |
| --- | --- |
| **对应接口** | `POST /file/upload`、`GET /file/download/{id}` |
| **对应页面** | **无独立页面**（能力被个人中心头像、审批附件、公告附件等复用；`/uploads/**` 为静态图片映射） |
| **权限码** | **无**（两个接口均不挂权限码，仅要求登录态；换头像 / 传附件是所有角色的基础能力） |
| **关键配置** | `file.storage-type`（默认 `local`，由 `@ConditionalOnProperty` 决定装配哪个 `FileStorageService` 实现）；`file.base-path` 默认 `F:/GitHub/OAStem/storage/files`；`file.access-prefix` 默认 `/uploads`；`file.max-size-mb` 默认 `10`；`spring.servlet.multipart.max-file-size=10MB`、`max-request-size=20MB` |
| **后缀白名单** | `jpg jpeg png gif bmp webp pdf doc docx xls xlsx ppt pptx txt csv zip rar 7z`（小写、不带点；白名单而非黑名单） |
| **相对路径规则** | `yyyy/MM/{32位uuid}.{suffix}`；**库中只存相对路径**，不含存储根目录 |
| **错误码** | `4001` 上传文件不能为空 / `4002` 不支持的文件类型 / `4003` 文件大小超出限制 / `4004` 文件不存在或已被删除 / `4005` 文件上传失败，请稍后重试 / `4006` 文件路径非法 |
| **关键响应约定** | 上传返回 `Result{id, fileName, url, fileSize, fileType}`；下载成功返回**二进制流 + `ResponseEntity`**（**不使用 `Result` 包装**），失败时由全局异常处理返回 `Result` JSON（HTTP 仍为 200） |
| **依赖模块** | M11 个人中心（头像上传与白名单校验来源）、M14 操作日志（业务接口调用产生的副作用比对） |

### 本模块执行前置（在 3.2 通用前置之外）

1. 基线核对：`oa_file` = **0 条**；存储根目录 `F:/GitHub/OAStem/storage/files` 存在且**为空**（本模块结束后须回到该状态，见 7.2-3「物理文件同步清理」）。
2. 已准备测试文件：`D-FILE-CN`（中文名，如 `测试文档.pdf`）、`D-FILE-BIG`（> 10MB）、`D-FILE-FAKE`（内容为脚本、扩展名为 `.jpg`），以及 `t_ok_1kb.png`（约 1KB 合法图片）、`t_empty.bin`（0 字节）、`t_exact10m.pdf`（恰好 **10485760** 字节）。
3. 已取得 admin 令牌；另准备第二身份 `t_file_b`（用于越权与可见性比对）。
4. 已确认 `file.base-path` 当前值为 `F:/GitHub/OAStem/storage/files`；`TC-FILE-09` 会临时改写该配置并**重启服务**，须在其余任务全部完成后再执行。
5. 本机 curl 上传必须加 `--noproxy '*'`，且 `-F "file=@<绝对路径>"`（见 3.4-1 / 3.4-2）。
6. 已理解响应约定：上传 / 下载的**业务失败**均返回 HTTP `200` + 业务码；仅认证失败返回 HTTP `401` + `code=401`。

**数据校验**

```sql
SELECT id, file_path,
       file_path LIKE '%:%'          AS has_drive,
       file_path LIKE '/%'            AS has_leading_slash,
       file_path LIKE '%storage%'     AS has_root_hint,
       file_path REGEXP '^[0-9]{4}/[0-9]{2}/[0-9a-f]{32}\\.[a-z0-9]+$' AS path_form_ok
FROM oa_file ORDER BY id DESC LIMIT 1;
-- 预期：has_drive=0、has_leading_slash=0、has_root_hint=0、path_form_ok=1
```

**关键结论**

1. 上传返回 `id` 与访问 `url`；落库字段 `file_name` / `file_suffix` / `file_size` / `file_path` 与实际一致，磁盘文件已落盘。
2. 相对路径严格为 `yyyy/MM/{32位uuid}.{suffix}`，**库中不含存储根目录**（`F:/GitHub/OAStem/storage/files` 或盘符均不出现），因此整体迁移只需改 `file.base-path`。
3. 空文件 → **4001**；白名单外扩展名（`.exe/.sh/.php`、无扩展名、`a.PNG.exe` 双层后缀）全部 → **4002**；大写 `.PNG` 按小写白名单放行。
4. 11MB 文件 → **4003**「文件大小超出限制」，**未被框架层打成 500**（说明业务层大小校验先于/优于 `MaxUploadSizeExceeded` 兜底生效）。
5. 下载 200 且内容与上传字节完全一致；`Content-Disposition` 同时给 `filename="..."` 与 `filename*=UTF-8''...`（中文名走 RFC 5987，浏览器取后者）；`download_count` 累加。
6. 不存在 id、已逻辑删除的文件均返回 **4004**；未认证 **401**。
7. 路径穿越 5 种写法（`..%2f`、`../`、`1/../../`、`abc`、`-1`）全部未泄露文件：前三种被 Tomcat/Spring 先行拒绝（400），`abc` 走参数类型错误（400），`-1` 走业务 4004。

**观察项（非缺陷）**

- 路径穿越的 `..%2f` 形态返回的是 Tomcat 默认 HTML 错误页，而非项目统一的 `Result` JSON。安全性没问题（未泄露文件），但**响应格式与全局约定不一致**；如后续要求「所有错误统一 JSON」，需在容器层加 `ErrorPage` 映射。

**缺陷**：**0 项**。

**数据处置**：测试上传的 5 个文件（png/txt/pdf/大写PNG/中文名）已按 `file_path` 逐个删除磁盘文件并物理删除 `oa_file` 记录，残留 **0**；未触碰既有文件记录。
