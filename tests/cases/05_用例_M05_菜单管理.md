## 模块信息

| 项 | 内容 |
| --- | --- |
| **对应接口** | `GET /system/menu/tree`、`POST /system/menu`、`DELETE /system/menu/{id}`、`PUT /system/menu/{id}/status` |
| **对应页面** | `/system/menu`（`views/system/menu/index.vue`）；副作用观测面：全站侧边栏（`/auth/menus` 渲染） |
| **权限码** | `system:menu:query`（树）、`system:menu:add` / `system:menu:edit`（保存，**`hasAnyAuthority` 任一即可**）、`system:menu:delete`（删除）、`system:menu:edit`（启停） |
| **关键结构** | `oa_menu` **无 `is_deleted` 字段**（用 `status` 控制启停）→ 删除为**物理删除**；`uk_menu_code` 唯一索引；`menu_type`：`1=目录 / 2=页面(菜单) / 3=按钮` |
| **关键配置** | 分页/树接口**不分页**，`/system/menu/tree` 一次返回全量（含按钮、含 `visible=0`、含 `status=0`） |
| **依赖模块** | M01 登录与认证（`/auth/menus` 下发与令牌 `perms`）、M03 角色管理（`oa_role_menu` 授权）、M14 操作日志（`@OperationLog` 审计落库） |

### 本模块执行前置（在 3.2 通用前置之外）

1. **PRE-M05-1** 已按 3.3 核对数据基线：`SELECT COUNT(*) FROM oa_menu;` = **63**、`SELECT COUNT(*) FROM oa_role_menu WHERE role_id=1;` = **63**（目录 4 + 页面 15 = 19 个侧边栏节点，按钮 44；2026-09-29 新增 `system:user:import` 后由 62 变更）。
2. **PRE-M05-2** 执行前已对该两张表做**行级备份**（`oa_menu`、`oa_role_menu`），本模块是对权限源头的写操作，**任一条用例结束后必须把 `visible` / `status` / 授权行还原**，收尾按 7.2.1 复核。
3. **PRE-M05-3** 本模块新增的临时菜单 id 会落在 63~100 之外的区间，**必须逐条记录新增返回的 id**，用例结束时 `DELETE FROM oa_menu WHERE id IN (...)` 物理清除（业务接口删除亦可，但需确保 `oa_role_menu` 无残留）。

5. **PRE-M05-5** 已理解 3.4-4「权限两个数据源」：`/auth/menus` **实时查库**（改菜单立即生效），接口鉴权读 **JWT `perms`**（8 小时不刷新，改权限后必须**重新登录**）。本模块 `TC-MENU-06` 直接以此判定。
6. **PRE-M05-6** 本模块所有分页类查询（如角色菜单分配页）参数名为 `pageNo` / `pageSize`（非 `pageNum`），与服务端 DTO 字段一致。

#### UC-MENU-02-B2 ｜ 树形结构的自身引用与循环引用不得导致死循环（回归点）

| 字段 | 内容 |
| --- | --- |
| **优先级** | P1 |
| **场景类型** | 边界条件 |
| **测试维度** | 功能, 回归 |
| **关联任务** | TC-MENU-02 |
| **关联接口** | `GET /system/menu/tree` |

**前置条件**

1. 见 3.2 通用前置条件
2. 已用 `D-ADMIN` 取得令牌；已备份 `oa_menu`
3. 已记录基线节点总数 62

**测试步骤**

1. 用 SQL 插入两个按钮型节点 A、B，并令 A.parent_id = B.id、B.parent_id = A.id（构成**环**）
2. 发送 `GET /system/menu/tree`，记录 HTTP 状态码、响应耗时、是否出现 5xx
3. 用 SQL 把 A.parent_id 改为 A.id（**自身引用**），再次发送 `GET /system/menu/tree`，记录 A 是否出现在结果中
4. 依次删除 A、B（先断开引用再物理删除），复核节点总数回到 62

**预期结果**

1. 步骤 2：`code = 200`，HTTP 状态码**不是 5xx**；响应耗时 < 3 s；后端日志中**无 `StackOverflowError`**
2. 步骤 2：A、B 因互相成为对方父节点而**不出现**在返回树中（实现按 `parentId` 装配，环内节点无根可达 → 被排除），节点总数 = 63（不出现即不计入）
3. 步骤 3：自身引用的节点 A 被当作**根节点**出现在顶层（实现判定 `parent.getId().equals(menu.getId())` → 走 root 分支），其 `children = []`，节点总数 = 63 + 1
4. 全程不出现死循环、超时、`code = 5000`
5. 步骤 4 复核：`SELECT COUNT(*) FROM oa_menu;` 回到 `62`

> **判定要点**：本用例只验证「**不得死循环 / 不得 5000 / 不得超时**」。若树中出现环导致接口 500 或响应超时 → **P1 缺陷**（树装配缺环检测）。环内节点被静默丢弃属**可接受实现**，但须在用例记录中写明「环数据不可见」这一客观行为。

**数据校验**

```sql
-- 构造（示例，实际 id 以插入返回为准）
INSERT INTO oa_menu (menu_name, menu_code, parent_id, menu_type, sort, visible, status)
VALUES ('T环A', 't:tmp:cyc_a', 0, 3, 1, 0, 1);
SET @a = LAST_INSERT_ID();
INSERT INTO oa_menu (menu_name, menu_code, parent_id, menu_type, sort, visible, status)
VALUES ('T环B', 't:tmp:cyc_b', @a, 3, 1, 0, 1);
SET @b = LAST_INSERT_ID();
UPDATE oa_menu SET parent_id = @b WHERE id = @a;   -- 形成 A→B→A 环

-- 清理
UPDATE oa_menu SET parent_id = 0 WHERE id IN (@a, @b);
DELETE FROM oa_menu WHERE id IN (@a, @b);
```
