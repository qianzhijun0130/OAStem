| **对应页面** | `/system/dept`（部门管理，树形表格）、`/system/user`（用户表单的部门树选择器，验证停用部门的可选性） |

| **依赖模块** | M02 用户管理（`oa_user.dept_id` 与 `company_id` 推导的源头）、M01 登录与认证（停用部门对权限的影响验证）、M14 操作日志（`@OperationLog` 留痕） |

3. 已用 admin 登录并取得 token

**测试步骤**

1. 发送 `GET /system/dept/tree`，**不带任何参数**
2. 记录 `code` 与 `data` 的顶层节点数
3. 递归展开树，统计节点总数与最大层级深度
4. 列出 `data[0]` 的全部字段名
5. 检查每个节点的 `children` 字段是否存在，且叶子节点为 `[]`
6. 检查同级节点的排序是否为 `sort` 升序、`sort` 相同时 `id` 升序
7. 核对每个节点的 `parentId` 与其在树中的实际父节点 `id` 是否一致

**预期结果**

1. HTTP 状态码 `200`，`code = 200`
2. `data` 为数组，**顶层节点数 = `1`**（仅根部门 id=1，其余全部为其后代）
3. 节点总数 = `oa_department` 中全部记录数（基线 4 + 测试部门数），**无节点丢失、无重复节点**
4. `data[0]` 字段集合为：`id`、`parentId`、`deptName`、`deptCode`、`companyId`、`leaderId`、`leaderName`、`deptType`、`sort`、`status`、`createTime`、`children`
5. 每个节点均含 `children` 字段；叶子节点为 `[]`（**不是 `null`**、不是缺字段）
6. 同级排序：按 `sort` 升序，`sort` 相同按 `id` 升序（如根下 `技术部(sort=1)` → `人事部(sort=2)` → `财务部(sort=3)` → 测试部门）
7. 每个 `children[i].parentId` 等于其父节点 `id`；根节点 `parentId = 0`
8. `leaderId` 与 `leaderName` 均为 `null`（符合 `PRE-M04-2` 基线），**不报错**

**数据校验**

```sql
SELECT id, parent_id, dept_name, dept_code, company_id, leader_id, dept_type, sort, status
FROM oa_department WHERE is_deleted = 0 ORDER BY sort ASC, id ASC;

-- 节点总数与响应逐项核对
SELECT COUNT(*) AS total_node FROM oa_department WHERE is_deleted = 0;

-- 层级深度核对（期望最深 4 层：1 → A1 → A2 → A3）
SELECT id, dept_name, parent_id FROM oa_department WHERE is_deleted = 0 ORDER BY parent_id, sort;
```

3. 场景 C：`code = 200`；该自引用节点出现在顶层（`parentId` 等于自身时不挂到自己身上），**不得**因此进入无限递归或栈溢出

5. 用例结束前必须清理场景 A、C 的脏数据，并断言 `SELECT COUNT(*) FROM oa_department WHERE parent_id = 999999 OR parent_id = id` 为 `0`

**数据校验**

```sql
SELECT COUNT(*) FROM oa_department WHERE parent_id = 999999;   -- 清理后预期 0
SELECT COUNT(*) FROM oa_department WHERE parent_id = id;       -- 清理后预期 0
SELECT COUNT(*) FROM oa_department WHERE is_deleted = 0;       -- 回到基线 + 测试部门数
```

#### 根因修正（重要）

`M04-D03` 原描述的根因「`submitting` 置位晚于校验」**不是实际成因**。对照实测：校验耗时远小于 45 ms，那个窗口根本没被踩到。真实窗口是——

> **保存请求约 90 ms 就返回并复位了守卫，而 Element Plus 弹窗的关闭动画还要约 300 ms**。这段「请求已回来、弹窗尚未消失」的窗口里按钮重新可点（`disabled` 序列 `#1 可点 → #2 loading → #3 可点 → #4 loading → #5 可点`），连点依次打进 3 次 POST。

**只加闸门 + 提前置位挡不住该窗口**，必须叠加「成功后不复位」才修得掉。此结论与 `M01` 登录按钮缺陷**同源**（那里是 `router.push` 未 await + `finally` 立即复位）。
