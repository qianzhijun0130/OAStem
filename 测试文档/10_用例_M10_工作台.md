3. 已按下方 SQL 造数：**仅**在当前月与 5 个月前各插入 2 条、1 条审批单，其余 4 个月无数据

**测试步骤**

1. 执行下方 `INSERT` 造数 SQL（时间分别为「当前月 5 日」与「5 个月前 5 日」）
2. 发送 `GET /dashboard/overview`，取出 `data.monthlyTrend`
3. 列出各项的 `label` 与 `total`，并与 SQL 按月经分组结果比对

**预期结果**

1. `monthlyTrend` 长度 = **`6`**
2. `label` 依次为当前月往前推 5 个月的连续 `yyyy-MM`，相邻两项月份差恰为 1
3. 有数据的两个月 `total` 分别为 `2` 与 `1`；**其余 4 个月 `total = 0`**（补零点存在）
4. `total` 为数值 `0` 而非 `null`、而非被省略的数组元素
5. 折线图 x 轴为 `6` 个刻度（前端显示为「N月」），中间不出现跨月的直连段

**数据校验**

```sql
-- 造数与核对：以「近 6 个月」为窗口按月经分组
SELECT DATE_FORMAT(create_time, '%Y-%m') AS label, COUNT(*) AS total
FROM oa_approval_instance
WHERE is_deleted = 0 AND create_time >= DATE_FORMAT(DATE_SUB(CURDATE(), INTERVAL 5 MONTH), '%Y-%m-01')
GROUP BY label ORDER BY label;
-- 预期：仅 2 行（当前月=2、5 个月前=1），其余 4 个月不在结果集中 → 由接口补 0
```
