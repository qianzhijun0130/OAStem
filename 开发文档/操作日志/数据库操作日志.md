## 2026-10-01-01 逻辑删除唯一索引改造（路径 D）：7 张表加生成列 active_flag + 唯一索引改复合键

**改动类型**：表结构变更（索引 + 新增生成列）+ 历史数据修复
**原因**：用户「选择行业内最推荐的方案执行」。MySQL 无 PostgreSQL 的 partial unique index（`WHERE is_deleted = 0`），业界通行替代手法是**生成列 + 复合唯一索引 + NULL 语义**。
**前置安全网**：全量备份 `F:/tmp/pathD_backup/backup_pathD_202610010100.sql`（7 张表，含 CREATE + INSERT）；DDL 前置检查确认 7 张表均无「同编码多行存活」（否则新唯一索引建不上）。

### 一、变更内容

对 7 张表统一执行：

```sql
ALTER TABLE <t>
  ADD COLUMN active_flag TINYINT
      GENERATED ALWAYS AS (IF(is_deleted = 0, 1, NULL)) VIRTUAL
      COMMENT '仅供唯一索引使用：存活=1，已删=NULL（利用 MySQL 唯一索引允许多个 NULL）',
  DROP INDEX <uk_x>,
  ADD UNIQUE KEY <uk_x> (<编码列>, active_flag);
```

| 表 | 唯一索引 | 编码列 |
| --- | --- | --- |
| `oa_user` | `uk_username` | `username` |
| `oa_role` | `uk_role_code` | `role_code` |
| `oa_department` | `uk_dept_code` | `dept_code` |
| `oa_dict_type` | `uk_dict_type` | `dict_type` |
| `oa_flow_definition` | `uk_flow_code` | `flow_code` |
| `oa_company` | `uk_company_code` | `company_code` |
| `oa_meeting_room` | `uk_room_code` | `room_code` |

**原理**：存活行 `active_flag=1` → 唯一索引按 `(编码, 1)` 约束，同编码只能有一条存活行；已删行 `active_flag=NULL` → MySQL 唯一索引允许多个 NULL，故任意多条已删行互不冲突。等价于 PostgreSQL 的 `CREATE UNIQUE INDEX ... WHERE is_deleted = 0`。

**未改动**：`is_deleted` 保持 `TINYINT NOT NULL DEFAULT 0`（0/1 语义），符合《阿里巴巴 Java 开发手册》建表规约对 `is_xxx` 字段的要求。
