## 2026-09-29-08 修复登录后跳转 404（根路径未声明路由 · P1，2026-09-28-03 的修复无效）

- **改动类型**：缺陷修复（P1）+ 路由契约显式化 + 两处硬编码跳转清理
- **涉及文件**：
  - `src/router/index.ts` — 在 `constantRoutes` 中**显式声明** `/`（`name: 'Root'`，`component: { render: () => null }`）
  - `src/views/login/index.vue` — 登录成功后的默认跳转目标由硬编码 `/dashboard` 改为 `/`，并补 `query.redirect` 的类型收窄
  - `src/views/error/404.vue` —「返回首页」按钮由 `router.push('/dashboard')` 改为 `router.push('/')`
  - `src/layout/components/Navbar.vue` — 面包屑「首页」由 `{ path: '/dashboard' }` 改为 `{ path: '/' }`
  - `src/router/dynamic.ts` — 仅补注释，说明「路由级 redirect 先于全局守卫执行」这一陷阱

### 一、故障现象

用户反馈：**登录成功后没有进入工作台，而是被重定向到 404 页面。**

### 二、根因（本次实测定位，有控制台证据）

`permission.ts` 的守卫里本来就有一段「`to.path === '/'` → 取菜单树里第一个 `menuType=2` 的菜单作为落地页」的逻辑（2026-09-28-03 加的），但**这段代码永远不可达**。

在守卫入口临时插桩后，Playwright 实测控制台输出：

```
[GUARD] {"path":"/",   "matched":0,"token":true,"loaded":false,"menus":0}  ← 第 1 次
[GUARD] {"path":"/404","matched":1,"token":true,"loaded":true, "menus":5}  ← 第 2 次
```

**第 2 次进入守卫时 `to.path` 已经是 `/404`**，从来没有出现过第二次 `path === '/'`。四步链路：

1. 首次导航到 `/`：路由表里**没有 `/`**（`constantRoutes` 只声明了 `/login`、`/profile`、`/404`），`to.matched = 0`，守卫以 `to.path === '/'` 进入；
2. `userStore.loaded === false` → `await loadUserInfo()` 注册动态路由，其中包含兜底路由 `/:pathMatch(.*)*`（`router/dynamic.ts`）；
3. 守卫随后 `next({ ...to, replace: true })` **重新导航 `/`**。此时兜底路由已注册，`/` 被它匹配；
4. 兜底路由带的是**路由级 `redirect: '/404'`**，而**路由级 redirect 在全局守卫之前执行** → 守卫拿到的 `to.path` 已经是 `/404` → 那段 `/` 分支不可达 → 进 404 页。

**触发条件**：必须是「**从根路径进入站点**」（浏览器地址为 `/`，或刷新在 `/`），此时未登录会被带到 `/login?redirect=%2F`，登录后 `router.push('/')` 命中该缺陷。若直接打开 `/login` 登录，`redirect` 为空、默认目标是 `/dashboard`，**不复现**——这正是 2026-09-28-03 手工验证时误判为「已修复」的原因。

### 三、为什么 2026-09-28-03 的修复无效

- **诊断是对的**：该条日志已准确指出「根路径 `/` 没有任何路由定义 → 命中兜底规则 → 重定向 `/404`」（第 3、4 步）。
- **修复是错的**：它绕过问题、在守卫里新增了一段 `/` 分支，但没有把 `/` 声明成路由。而只要 `/` 未声明，就一定会被兜底路由的**路由级 redirect** 抢先改写——守卫根本没机会看到 `/`。等于**在一条永远不会被执行的代码路径上写逻辑**。
- **验证方式不足以发现**：该条的验证只有「`npm run build` 退出码 0，✓ built in 3.08s」。**构建成功 ≠ 功能正确**：路由逻辑缺陷在类型检查与打包阶段完全静默。教训是这类「跳转/落地页」缺陷必须用真实浏览器跑一遍目标路径。

### 四、修复方案

核心是**让 `/` 成为一条已声明的路由**，使其匹配权重（静态段）高于兜底路由（catch-all 参数），守卫里的 `/` 分支才能真正执行：

```ts
// src/router/index.ts（constantRoutes 首项）
{
  path: '/',
  name: 'Root',
  component: { render: () => null },   // 占位：真实落地页由守卫决定，该组件不会被渲染
  meta: { title: '首页', hidden: true },
}
```

同时清理**三处硬编码 `/dashboard`** 的跳转目标——它们同样会让「没有工作台权限的角色」直接撞 404，与守卫注释里「不能硬编码跳 `/dashboard`」的约定自相矛盾：

| 位置 | 原值 | 现值 |
|---|---|---|
| `views/login/index.vue` 登录后默认目标 | `/dashboard` | `/` |
| `views/error/404.vue`「返回首页」按钮 | `/dashboard` | `/` |
| `layout/components/Navbar.vue` 面包屑「首页」 | `/dashboard` | `/` |

并在 `router/dynamic.ts` 的兜底路由处补注释，说明「路由级 redirect 先于守卫执行 → 任何需要守卫分支处理的路径必须先在 constantRoutes 声明」，避免同类问题再次发生。

## 2026-09-28-03 修复登录后跳转 404（根路径无路由）

- **类型**：缺陷修复
- **文件**：`src/permission.ts`（新增 `firstAccessiblePath` + 根路径分支）、`src/router/dynamic.ts`（兜底路由补 name）

**故障现象**：管理员登录成功后进入 404 页，而非工作台。

**根因**：四步链路
1. 访问 `http://localhost:3000/`（根路径）时未登录 → 守卫跳转 `/login?redirect=%2F`
2. 登录页读取 `redirect` 参数得到 `/`，登录成功后执行 `router.push('/')`
3. **根路径 `/` 没有任何路由定义** —— 工作台实际路径是 `/dashboard`（由 `oa_menu.path` 下发）
4. 命中兜底规则 `/:pathMatch(.*)*` → 重定向 `/404`

**修复方案**：不硬编码跳 `/dashboard`（没有工作台权限的角色会被导向 404），改为在守卫中取菜单树里第一个 `menuType=2 && path` 的菜单作为落地页，无权限时才进 404。

**顺带修复**：`dynamic.ts` 的兜底路由原先没有 name，导致 `resetState()` 无法移除它，每次登录都会重复注册一条。已补 `name: 'CatchAll'`。

**验证**：`npm run build` 退出码 0，✓ built in 3.08s。

> ⚠️ **后续更正（见 2026-09-29-08）**：本次修复**实际无效**。诊断正确（根路径无路由定义 → 命中兜底规则），但方案错在「只在守卫里加 `/` 分支，却没有把 `/` 声明成路由」——只要 `/` 未声明，就会被兜底路由的**路由级 redirect** 抢先改写成 `/404`，守卫中那段 `/` 分支永远不可达。本例的验证方式（只跑 `npm run build`）无法发现路由逻辑缺陷，故被误判为已修复。2026-09-29-08 已用真实浏览器复现并给出有效修复。

**踩坑**：

1. **`@/` 别名 TS 不识别**（TS2307 批量报 Cannot find module）。vite.config.ts 有 alias，但 tsconfig 没有。需在 `tsconfig.app.json` 补 `paths`。
2. **`baseUrl` 在 TypeScript 6 已弃用**（TS5101）。只写 `paths`，不要写 `baseUrl`，路径相对 tsconfig 所在目录解析。
3. **axios 1.20 的 request 泛型变更**。响应拦截器已把 `ApiResponse` 解包为业务数据，但静态类型仍推导为 `AxiosResponseResult`，需用断言对齐运行时行为。
4. **本会话终端有 HTTP 代理**，curl 访问 127.0.0.1 会返回 502，必须加 `--noproxy "*"`。

**验证**：`npm run build`（含 `vue-tsc` 类型检查）→ 退出码 0，1685 个模块转换成功 ✅

## 【缺陷·待修】`.env.developmen` 文件名拼写错误

- **文件**：`vue3-admin-template/.env.developmen`
- **问题**：文件名少字母 `t`。Vite 在 `development` 模式下只加载 `.env.development`，当前文件不会被加载
- **后果**：开发模式下 `import.meta.env.VITE_APP_BASE_API` 取不到值（内容为 `/api`），axios 基础地址会失效
- **修复方案**：重命名为 `.env.development`
- **验证方式**：改名后 `console.log(import.meta.env.VITE_APP_BASE_API)` 应输出 `/api`
